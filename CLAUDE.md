# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

TapStory: an iOS app (SwiftUI + CoreNFC) that turns an iPhone into a screen-free storytelling appliance for toddlers. Tapping an NFC tag stuck to a toy or card plays a story, vocabulary word, or song. **Audio-only is the default and the core design goal** — the screen does not change at all when content plays unless a parent explicitly turns on the "Screen Display" setting. See the README for full product rationale; this file is about working in the code.

## Commands

The `.xcodeproj` is generated by [xcodegen](https://github.com/yonaskolb/XcodeGen) from `project.yml` and is **not committed** — regenerate it after adding/removing/renaming any source file, resource, or target setting:

```sh
xcodegen generate
```

Build (Simulator, no code signing needed):

```sh
xcodebuild -project TapStory.xcodeproj -scheme TapStory \
  -destination 'generic/platform=iOS Simulator' \
  -configuration Debug CODE_SIGNING_ALLOWED=NO build
```

Run the full test suite:

```sh
xcodebuild -project TapStory.xcodeproj -scheme TapStory \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -configuration Debug CODE_SIGNING_ALLOWED=NO test
```

Run a single test class or method (add `-only-testing:` once per target):

```sh
xcodebuild -project TapStory.xcodeproj -scheme TapStory \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -configuration Debug CODE_SIGNING_ALLOWED=NO \
  -only-testing:TapStoryTests/MediaResolverTests/testSpeechResolvesToTextVerbatim \
  test
```

Regenerate the bundled lullaby placeholder audio (the only bundled content that needs a real audio file rather than on-device speech — see Architecture):

```sh
./Scripts/generate_sample_audio.sh
```

Regenerate the shared 1024x1024 App Icon source (written into both `App/TapStory/Assets.xcassets/AppIcon.appiconset/` and `App/TapStoryWatch/Assets.xcassets/AppIcon.appiconset/` — same image, single-size icon set, no per-size exports needed on modern Xcode):

```sh
python3 Scripts/generate_app_icon.py
```

Capture App Store / landing-page screenshots (boots simulators, no manual interaction or XCUITest), then bake device-frame bezels into copies of them for display in README.md/the landing page (raw screenshots must stay unframed for possible App Store Connect reuse):

```sh
./Scripts/capture_screenshots.sh && python3 Scripts/frame_screenshots.py
```

Bump version, commit, push, and create a GitHub Release (which automatically triggers the TestFlight upload workflow):

```sh
./Scripts/release.sh [patch|minor|major|<version>]
```

**Never pass `-sdk iphonesimulator` (or any explicit `-sdk`) on these commands.** The app embeds a watchOS companion target (`TapStoryWatch`); an explicit `-sdk` forces that SDK onto the *entire* target graph, silently building the watch target for the wrong platform too, which compiles fine but fails at install time with an opaque "companion watch app validation" error. Plain `-destination` resolves each target to its own declared platform correctly.

There is no linter/formatter configured in this repo.

**To test on a physical device** (required for anything NFC- or Guided-Access-related — CoreNFC does not work in the Simulator at all): open `TapStory.xcodeproj` in Xcode, set your own Team under Signing & Capabilities, and run on an iPhone 7 or later.

## Architecture

### Tag stores an id, not content

The single fact that explains most of the NFC-adjacent code: a physical NFC tag never stores real content. It stores a `TagReference` (`{ schemaVersion, id }` — just a UUID string). The actual content — a story's pages, a vocab word's audio, everything — is a `ContentRecord` (`{ schemaVersion, type, payload }`) living in `TagLibraryStore`, a local JSON file, addressed by that id.

Flow on a tap: `NFCReaderService` decodes a `TagReference` off the tag → `PlaybackCoordinator` looks the id up via `TagLibraryStore.entry(withID:)` → gets a `ContentRecord` → dispatches `record.type` through `ActorRegistry` to the matching `ContentActor`.

This means: tag capacity is a non-issue (any cheap NTAG21x fits a UUID), but a tag only means something on the phone whose library still has that id — deleting a library entry or the app orphans any tag pointing at it. `NFCWriterService` writes only a `TagReference`, never a `ContentRecord`.

### Actor registry (open schema, no hardcoded type list)

`ContentRecord.type` is a dispatch key into `ActorRegistry`, which maps it to a `ContentActor` (protocol: `typeIdentifier`, `displayName`, `iconSystemName`, `canHandle(_:)`, `makeChildView(for:onFinished:)`). Built-ins are `story`, `vocab_card`, `music` (`App/TapStory/Actors/*`), registered in `ActorRegistry.registerBuiltInActors()`. Nothing else in the app — NFC read/write, the tag-authoring UI, the type picker — has a hardcoded list of types; they all read `ActorRegistry.shared.allActorTypes`. Add a new activity by writing a new `ContentActor` conformance and registering it there.

### MediaRef: three audio sources behind one type

Every actor's `audio` field is a `MediaRef { source, ref }` resolved by `MediaResolver`:
- `.bundled` — a file shipped in the app (`Resources/BundledContent/`, flattened to the bundle root by Xcode's Copy Bundle Resources step — code always looks up by filename only, never by subdirectory, even though the on-disk source tree is organized into subfolders).
- `.recording` — a parent's on-device voice recording (`RecordingStore`), addressed by UUID.
- `.speech` — literal text spoken live via `AVSpeechSynthesizer` at playback time (no file at all). This is the default authoring path. **A blank `.speech` ref is a real, meaningful value** meaning "speak this item's own caption/word/title instead" (`AudioPlaybackController.resolvingBlankSpeechRef`) — used throughout the bundled sample content so narration text isn't duplicated between the display field and the audio field.

### Screen Display: one playback path, two visibility states

`AppSettings.isScreenDisplayEnabled` (UserDefaults-backed, off by default) controls whether the screen ever visually changes. Rather than forking a separate "audio-only" code path, `ChildLockedShellView` always mounts the same `ContentActor` view (so its `AVAudioPlayer`/`AVSpeechSynthesizer` timing and page-auto-advance logic run identically either way) — when the toggle is off it's rendered at `.opacity(0)` / `.allowsHitTesting(false)` instead of being removed from the hierarchy. Error states are suppressed and cleared immediately the same way when the toggle is off, rather than showing briefly.

### NFC layer is isolated and can't be exercised in Simulator

`App/TapStory/NFC/` contains all CoreNFC-specific code (`NFCReaderService`, `NFCWriterService`, `TagReference+NDEF`), kept separate from `Core/` so the schema/business logic has no CoreNFC dependency. CoreNFC does not work in the iOS Simulator at all, so two `#if DEBUG`-only mechanisms exist purely for Simulator testing (zero footprint in Release builds):
- `DebugSimulateTapButton` — an in-app UI to manually pick bundled/library content and feed it through the same coordinator path a real tag read would use.
- `ScreenshotAutomation` — reads `TAPSTORY_SCREENSHOT_SCENE` from the environment on launch (set via `SIMCTL_CHILD_...` when using `simctl launch`) to jump straight into a given scene, used by `Scripts/capture_screenshots.sh`.

iOS's own "Ready to Scan" system sheet is layered on top of `IdleTapPromptView` for nearly the entire time it's visible — CoreNFC ties that sheet's lifetime 1:1 to the reader session, and the session has to run continuously for a zero-button tap to work (see `NFCReaderService`), so there's no API to keep listening without it showing. No app can restyle that sheet's title, icon, or color; the only customizable piece is one line of body text (`session.alertMessage`). It also typically covers close to the bottom half of the screen. `IdleTapPromptView`'s content is deliberately top-anchored rather than vertically centered for exactly this reason — centered content spends nearly all its time hidden behind the sheet.

`NFCReaderService` restarts the session on every invalidation to keep listening continuous, but distinguishes *why* it invalidated rather than always using the same delay: a user tapping the sheet's own Cancel button gets `parentGateRestartDelay` (see the parent-gate note below); a session that dies in under `fastFailureThreshold` (5s) for any other reason is treated as a genuine failure loop — not "no tag nearby yet," since real reads and the ~60s OS timeout both live far longer than that — and backs off exponentially up to `maxBackoffDelay` instead of hammering the NFC controller and re-flashing the sheet many times a second. `recentInvalidations` logs each event (error code, session lifetime, chosen delay) for on-device diagnosis via `NFCTagInspectorView`, since CoreNFC issues can't be reproduced in the Simulator or debugged over a cable in most real-world settings.

### Watch companion app

`TapStoryWatch` (`App/TapStoryWatch/`) is a modern single-target watchOS app (no separate WatchKit Extension target), embedded into `TapStory` via a `dependencies: embed` entry in `project.yml`. It's a remote control for the parent — toggle Screen Display, stop playback, or start a saved story from the wrist — specifically so acting on any of that never requires touching the phone a toddler is holding.

`Shared/WatchConnectivity/WatchMessage.swift` (`WatchCommand`, `PhoneStatus`) is compiled into *both* targets (listed in both targets' `sources:` in `project.yml`) rather than duplicated, so the wire format can't drift. Transport is `WCSession` (WatchConnectivity) — a local link between paired devices, no internet/accounts involved. `PhoneWatchConnectivityService` (iOS, in `App/TapStory/Watch/`) pushes a `PhoneStatus` snapshot via `updateApplicationContext` on every relevant change and applies incoming `WatchCommand`s to `AppSettings`/`PlaybackCoordinator`; `WatchConnectivityService` (watchOS) is the mirror image, sending commands and applying them optimistically to its local `status` before the phone confirms.

`WCSessionDelegate` has iOS-only required methods (`sessionDidBecomeInactive`/`sessionDidDeactivate`) that are marked *unavailable* on watchOS — and `TapStoryWatch`'s sources get compiled under both SDKs (once for real watchOS, once under iOS as part of `TapStory`'s embed step), so those two methods are wrapped in `#if os(iOS)` in the watchOS-side file.

### Child-facing views: background bleeds, content doesn't

`ChildLockedShellView` deliberately does *not* apply `.ignoresSafeArea()` to its outer `ZStack`. Each child view (`IdleTapPromptView`, `StoryPlayerView`, `VocabCardView`, `MusicPlayerView`, `PlaybackErrorView`) instead calls `.ignoresSafeArea()` on its own `.background(...)` only, so the black/white fill bleeds edge-to-edge while text/icon content stays within the safe area. Applying it at the shell level once caused `StoryPlayerView`'s title to render directly under the Dynamic Island on real devices — caught via the screenshot automation, not by eye. Any new top-anchored content in a child-facing view should follow the same pattern.

### TestFlight release automation

`.github/workflows/testflight.yml` (triggered on GitHub release creation/publication or manually via `workflow_dispatch`) archives, signs, and uploads a build via `xcodebuild -exportArchive` with `destination: upload` in its `exportOptionsPlist` — this Xcode version performs the App Store Connect upload directly during export, no separate `xcrun altool` step needed (and `method` must be `app-store-connect`; the older `app-store` value is rejected outright by this Xcode version, not just deprecated). All 7 required secrets are already configured: 4 from this machine's Apple Distribution identity, and 3 App Store Connect API key secrets recovered from this machine's `FA_ASC_KEY_ID`/`FA_ASC_ISSUER_ID`/`FA_KEY_LOCATION` env vars (a prior fastlane setup). Same `-sdk`-flag gotcha as local builds applies here (see above) — the workflow deliberately never passes one.

Four signing/packaging facts here are non-obvious and each one cost a full round of misleading errors:

- **The embedded watch target must keep `SKIP_INSTALL: YES`.** It ships inside `TapStory.app/Watch/`, so installing it standalone too puts a *second* `.app` in the archive's `Products/Applications/`. Xcode then can't identify the primary application and silently omits `ApplicationProperties` from the archive's `Info.plist`. Every distribution method subsequently rejects the archive as having no supported platform, and `-exportArchive` reports the entirely unrelated-looking `exportOptionsPlist error for key "method" expected one {} but found app-store-connect` — the `{}` is the *empty* set of valid methods, not a complaint about the string. The workflow asserts `ApplicationProperties` exists right after archiving so this fails loudly instead.
- **Release uses Manual signing, not Automatic.** Automatic signing's development-vs-distribution purpose resolution is unreliable via `xcodebuild` on the CLI (it kept choosing development even with a Distribution identity and `DEVELOPMENT_TEAM` set, then hard-conflicted with any explicit Distribution override). `project.yml` pins `CODE_SIGN_IDENTITY: "Apple Distribution"` plus a `PROVISIONING_PROFILE_SPECIFIER` per target, and the export options repeat the same mapping under `provisioningProfiles` with `signingStyle: manual`. Don't pass `CODE_SIGN_STYLE=Automatic` on the archive command — it undoes all of this.
- **Version keys must reference build settings.** The `info:` blocks set `CFBundleShortVersionString: "$(MARKETING_VERSION)"` and `CFBundleVersion: "$(CURRENT_PROJECT_VERSION)"`. xcodegen otherwise writes literal `1.0`/`1`, which silently overrides the per-run build number CI passes as `CURRENT_PROJECT_VERSION`, so every upload would arrive as build "1" and be rejected as a duplicate.
- **The NFC entitlement must be `TAG`, not `NDEF`.** `NDEF` is a long-deprecated value for `com.apple.developer.nfc.readersession.formats` (ITMS-90778, "NDEF is disallowed") — current App Store Connect validation rejects it outright regardless of deployment target. `TAG` is the modern replacement and fully covers `NFCNDEFReaderSession` scanning/writing (this app never uses `NFCTagReaderSession` directly), so it's an entitlement-only fix, no code changes needed. This only surfaces during the *upload* step (`xcrun altool --validate-app` / the live App Store Connect analysis after `-exportArchive` finishes) — a local `-exportArchive` with `destination: export` succeeds either way, since it never talks to Apple's servers.

### Landing page / App Store pages

`docs/` is a dependency-free static site (landing page, Privacy Policy, Terms, Support/FAQ) deployed to GitHub Pages by `.github/workflows/deploy-pages.yml` on every push to `main` that touches `docs/`. Screenshots under `docs/screenshots/` are generated, not hand-made — see `Scripts/capture_screenshots.sh`.
